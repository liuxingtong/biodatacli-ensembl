## 关于那 32 条题

按你说的，不做人工金标，全部由冻结数据推导，每题都记了 `source_of_truth`（哪个文件的哪一行支持这个答案）。

它的定位我改清楚了：**回归题，不是准确率评测**。作用是改代码时立刻发现哪里坏了、并锁住"准/诚/寸"的判定口径；同一份数据既出题又答题，只能证明内部一致，不能对外背书。这一点在控制台和 README 里都写明了，不夸大。

## 追加：全基因组建库完成

- 下载 1.0 GB（Ensembl 单流被限到 10–15 KB/s，24 路分块并发跑满 ~300 KB/s，约 55 分钟）
- 切分：10,709,126 行 GFF、3.09 Gb 序列，7 分 11 秒
- 25 条染色体分别建图：7 分 27 秒，产出 3.2 GB 分片
- 合并：2 分 36 秒 → `full/index/ensembl_grch38_r116.sqlite`，**3.07 GB**

结果：**2,413,526 节点 / 6,172,320 边**；78,733 基因、644,292 转录本、370,886 蛋白、1,319,589 外显子。24 个重复 key 被合并（每条染色体都带一个 assembly 节点）。

抽查：YWHAB 落 chr20、TP53/BRCA1 落 chr17（TP53 41 个转录本）、HBB 落 chr11，坐标与结构都对。

**这一版没有跨库引用**（`xref_nodes = 0`）：全基因组 BioMart 导出还没下，所以 UniProt/PDB 边、crosswalk 仍然只有 chr20 那份。这是明确的缺口，不是"全量"该有的样子。

可视化：`python3 viz/server.py --db full/index/ensembl_grch38_r116.sqlite --port 8766`，截图 `viz/screenshots/full-genome.png`。
